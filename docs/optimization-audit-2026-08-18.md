## 1. 结论摘要

本轮已完成确认范围内的安全、数据隔离、后台运行、运行日志、同步可靠性、配置校验和主要页面体验改进。任务报告现在只读取任务绑定邮箱且绑定当前同步来源的邮件；全局邮件页仍展示当前用户所有邮箱，并提供邮箱筛选。

手动运行和“立即同步”现在提交后台 `JobRun`，当前任务详情页默认折叠显示当前任务的运行信息，支持轮询、历史记录、取消和重试。管理员可以在管理页查看所有任务的脱敏运行摘要和阶段日志；普通用户不能跨越自己的任务权限范围。

本轮没有连接真实 IMAP、SMTP 或 AI 服务，没有删除现有 `var/` 数据，也没有自动提交代码。

### 3.2 报告范围、同步来源和报告质量

| 编号 | 原问题 | 当前状态与实现 |
| --- | --- | --- |
| MP-002 | 任务报告可能混入同一用户其他邮箱的邮件 | 已修复。报告通过 `MessageOccurrence.mailbox_id` 和 `Mailbox.sync_source_id` 限定任务绑定邮箱及当前同步来源；`/messages` 保持用户全邮箱视图并支持 `mailbox_id` 筛选。 |
| MP-003 | FETCH 分块失败仍推进同步游标 | 已修复。任一分块失败会让本次同步失败并保持旧游标，恢复后可重新抓取失败分块。 |
| MP-007 | 修改邮箱来源配置后沿用旧游标 | 已修复。邮箱地址、IMAP 主机、端口、TLS、登录用户名或文件夹变化会生成新的同步来源并清空游标；仅改密码或 SMTP 配置不重置 IMAP 来源。历史数据保留，但不进入新来源任务报告。 |
| MP-009 | 先取最新 N 封再应用规则，可能漏报 | 已修复。现在先按任务邮箱、同步来源和时间范围取候选，再执行规则，最后按时间倒序截取上限；报告和日志记录命中总数、实际纳入数量及截断提示。 |
| MP-020 | `received_at` 为 NULL 的邮件无法进入时间范围 | 已修复。报告时间使用 `MessageOccurrence.internal_date`，缺失时再回退到 `CanonicalMessage.received_at`，邮件模型和报告时间范围保持一致。 |
| MP-011 | 环境变量 Primary 回退时丢失数据库 Vision 配置 | 已修复。Primary 与 Vision 按角色独立合并数据库配置和环境变量回退，三种组合均有测试覆盖。 |
| MP-021 | AI 重试无退避且缺少模型连接诊断 | 已修复。AI 请求重试增加有上限的退避；模型管理页支持测试连接；日志只保留阶段、状态和脱敏诊断，不写入 API Key、正文或完整 Prompt。 |

视觉副模型失败时，主模型继续生成报告。报告处理说明、`model_trace` 和 JobRun 日志会标记视觉阶段降级，并说明报告未使用或未验证视觉证据；只有主模型失败才会使任务失败。

### 3.3 后台运行、并发和调度

| 编号 | 原问题 | 当前状态与实现 |
| --- | --- | --- |
| MP-004 | 同一 Cron 时刻失败后每 30 秒重复执行 | 已修复。任务记录 `last_scheduled_fire_at`，计划运行使用稳定的 `schedule:{task}:{fire_time}` run key；同一计划时刻只创建/尝试一次，失败后由用户手动重试，下一 Cron 时刻照常执行。 |
| MP-008 | 手动运行占用网页请求且没有服务端运行锁 | 已修复。手动运行和立即同步都创建 queued JobRun，由 worker 执行；任务级和邮箱级 `active_run_key` 锁保证同一任务/邮箱不会并发同步。 |
| MP-016 | 每个 Web 请求都新建 Engine 和连接池 | 已部分优化。Web 依赖现在复用应用级 session factory；CLI 和测试仍可显式创建独立 factory。后续可继续完善 lifespan 资源释放和更细的连接池策略。 |

JobRun 支持 `queued`、`running`、`success`、`failed`、`canceled` 状态，记录运行类型、阶段、开始/结束时间、阶段事件、汇总数据和脱敏错误摘要。取消采用协作式处理：worker 在阶段切换和外部调用返回后检查取消标记，不强制杀死正在进行的单次请求。

| 编号 | 原问题 | 当前状态与实现 |
| --- | --- | --- |
| MP-006 | 复制邮箱没有完整复制端口/TLS/文件夹，测试配置可能与创建配置不一致 | 已修复。复制会创建独立配置副本，完整复制 IMAP/SMTP 主机、端口、TLS、用户名、文件夹和加密凭据；前端填充同一份可编辑副本，密码不回显。 |
| MP-018 | 多任务/多进程下配额和同步缺少原子保护 | 部分修复。任务级和邮箱级运行锁已加入，附件先写入临时文件再原子替换；多进程配额事务和跨进程部署边界仍需后续增强。 |

## 5. 当前任务运行日志设计

### 用户侧

- 入口：任务详情页“当前任务运行”区域；
- 默认状态：折叠，只显示最近一次运行或当前运行的一行摘要；
- 展开后：显示阶段、状态、时间、同步数量、附件数量、规则命中数、纳入报告数、投递结果和错误摘要；
- 轮询：queued/running 状态每 2 秒刷新，终态保留在当前任务详情页，不自动跳转；
- 历史：单独的“历史运行记录（当前任务）”折叠区，只列出当前任务的 JobRun；
- 操作：运行中可取消，失败或取消后可重新运行，成功生成报告时提供“查看报告”链接。

### 管理员侧

- `/admin/jobs` 显示跨用户、跨任务的运行汇总；
- 管理员可查看单条 JobRun 的阶段日志、汇总、错误和报告关联；
- 普通用户不可访问管理员运行记录，也不能通过任务详情接口读取其他任务的日志；
- 日志不包含密码、API Key、完整邮件正文、原始附件或完整模型提示词。

### 保留策略

详细阶段事件默认保留 90 天或每个任务最近 100 次运行，取较大范围；超过范围后清理详细事件，但保留 JobRun 汇总、状态、时间和失败原因。清理逻辑在 worker 轮询时执行。

## 6. 已确认的产品决策与验收口径

以下决策已逐项与用户确认，并已作为实现依据：

1. 报告只处理任务绑定邮箱；邮件页展示当前用户所有邮箱并支持筛选。
2. 同一 Cron 时刻只自动尝试一次；失败后手动重试。
3. 手动运行和立即同步后台执行，当前任务页显示默认折叠日志。
4. 日志只显示当前任务；管理员才可看所有任务的脱敏日志。
5. 运行日志保留最近 90 天或每任务最近 100 次的详细事件。
6. 报告先规则筛选，再按上限截取，并显示截断信息。
7. 邮箱来源变化重置游标并建立来源边界；密码/SMTP 单独变化不重置。
8. 复制邮箱为独立副本，互不影响，密码不回显。
9. 立即同步只执行 IMAP 同步，不执行 AI 归纳和投递。
10. 运行完成后停留当前任务页，成功提供报告链接，失败保留错误和重试入口。
11. 失败重运行默认从同步阶段开始；投递失败保留独立投递重试入口。
12. 当前任务无运行中记录时显示最近一次，并可展开当前任务历史。
13. 管理员查看所有任务摘要和脱敏阶段日志。
14. 取消为协作式取消，不强杀正在进行的单次外部请求。
15. Vision 失败不阻断主模型，报告明确标记视觉降级。

## 7. 仍待后续优化或真实环境验收的事项

以下事项没有在本轮擅自扩展实现，保留为后续迭代：

### MP-015：弱内容哈希的误合并风险

缺少 Message-ID 时，主题、发件人、收件人和正文相同的邮件仍可能被当成同一封，尤其是附件不同或重复发送的情况。后续应把附件摘要、Cc、日期和来源身份纳入候选身份，并在冲突时保留多个 occurrence 或记录告警。

### MP-017：规则求值的 N+1 查询

规则求值仍可进一步预加载附件并缓存同一轮报告中的规则数据；简单字段可先做 SQL 过滤，复杂 DSL 再在 Python 中求值。

### MP-019：附件、转换结果和旧邮箱数据的生命周期清理

当前不会自动删除现有运行数据。后续应先实现可审计的 dry-run、统计、标记和孤儿资源回收，再明确报告/邮件历史保留策略。

### MP-022：非 SQLite 数据库支持边界

当前初始化和全文搜索依赖 SQLite FTS5。配置校验和部署文档应明确当前支持边界；如需 PostgreSQL 等数据库，应提供独立搜索实现后再宣称支持。

### 真实服务与部署验收

需要在隔离环境单独验证：IMAP UIDVALIDITY/分块失败恢复、SMTP TLS/认证、OpenAI-compatible 模型路由和超时、生产反向代理下的 CSRF/Session、单 worker 与多 worker 部署差异、真实附件转换和配额边界。本轮测试使用 Fake Provider，不代表这些外部系统已验收。

## 8. 数据库与运维注意事项

本轮新增/调整了 `Mailbox.sync_source_id`、`Mailbox.active_run_key`、`Task.last_scheduled_fire_at`、`Task.active_run_key`、`MessageOccurrence.source_id` 以及 JobRun 的运行类型、调度时间、状态、取消标记和日志字段。

项目当前开发阶段按约定不维护数据库迁移文件，模型变化通过 `init-db` 创建缺失表结构；若本地开发数据库需要应用字段变化，应使用项目既有 `reset-db` 流程重建本地数据库，不直接手工修改运行数据库，也不删除用户现有 `var/` 数据。进入需要保留数据的阶段后，再引入版本化迁移。
